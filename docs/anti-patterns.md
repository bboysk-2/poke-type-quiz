# アンチパターン（やってはいけないこと）

| やりがち | なぜ駄目か | 代わりに |
|---|---|---|
| コンポーネント内で `fetch` | 表示とI/Oが混ざりテスト不能 | routes で取得し props で渡す |
| atoms から molecules を import | 階層が崩れ影響範囲が読めなくなる | 合成するなら上の階層へ移す |
| `Math.random()` 直呼び | 結果が非決定的でテストが落ちたり通ったりする | `Random` を注入 |
| PokeAPI のレスポンスを `as Pokemon` で信じる | API 変更で実行時に壊れる | 型ガードで検証して domain 型に変換 |
| テストを消す/`.skip` で通す | ゲートの意味がなくなる | 実装を直す。仕様変更なら計画を更新して承認を得る |
| `eslint-disable` / `@ts-ignore` / `@ts-expect-error` | センサーを目隠しする | 根本修正。どうしても必要なら計画に理由を書く（verify が検出する） |
| 使わない export・ファイルを残す | エントロピー増大 | 削除する（knip が検出する） |
| 計画にない機能を「ついでに」追加 | 受け入れ基準と検証がずれる | todo.json に新タスクとして追加 |
| AGENTS.md に詳細を書き足す | 地図が百科事典化してノイズになる | docs/ に書いて AGENTS.md からリンク |
| 「たぶん動く」で完了宣言 | 検証されていない | `pnpm verify` と verifier エージェントの確認後に宣言 |
